# QuickLogin 官网与受控下载设计

日期：2026-09-28
状态：2026-09-28 用户已确认设计；实施计划待审阅，尚未开始产品实现或部署。

## 目标与已确认范围

在 quicklogin.cqu.moe 建立 QuickLogin 独立产品官网，让用户了解插件功能、下载内测包并完成安装。介绍公开，下载仅向已登录 Auth 且有 QuickLogin 内测资格的用户开放；没有申请入口或候补名单。

包含首页、下载与安装、常见问题、隐私说明、更新记录五类页面。视觉采用浅色背景、清晰标题、真实插件界面和克制的品牌色。按 emil-marketing-pages 与 emil-design-foundations 执行设计。

## 页面与视觉

- `/`：以“少一次登录，多一点顺畅。”作为建议主标题，说明减少重复学校登录的用途，展示真实插件界面；随后解释独立设备会话、暂停与退出、安装授权步骤。文案只描述现有能力，不承诺永久登录或零验证。
- `/download/`：显示当前可下载版本、内测标记、包大小、SHA-256、三态下载入口；提供 ZIP 解压、Chrome 开发者模式加载、Auth 授权和更新原目录的图文步骤。未完成浏览器验证的版本不包装为稳定版。
- `/faq/`：解释内测资格、安装与升级、已有学校登录的处理、重新授权、暂停与退出。资格不足仅提示暂未开放。
- `/privacy/`：按实际实现说明插件权限、Cookie 同步、Auth 服务与扩展的数据边界、现有遥测及设备撤销。扩展不读取学校密码不等于 Auth 不处理凭据，不使用笼统的“所有数据只在本地”表述。
- `/changelog/`：从核验后的发布记录整理面向用户的更新，不暴露内部运维记录、账号或日志。

延续现有蓝色盾形标记与系统字体；布局使用留白与文字层级，首屏以文案和插件界面形成非对称布局。每个视图一个主要操作。移动端内容自然堆叠，安装步骤说明需要桌面 Chrome。无滚动入场、自动轮播或视差效果。按钮具有键盘焦点与按压反馈，尊重减少动态效果设置。

## 下载状态契约

| 条件 | 唯一业务状态文案 | 行为 |
| --- | --- | --- |
| 未登录或会话失效 | 请登录后下载 | 跳转 Auth 登录，携带受限的官网返回地址 |
| 已登录且具备内测资格 | 下载 | 用户点击后发起受控下载 |
| 已登录但没有内测资格 | 内测中，暂未开放 | 普通状态说明，不提供下载或申请入口 |

加载及网络故障是临时交互状态，不增加第四种业务资格状态。查询尚未完成时保留布局且不允许下载；错误时给出重试，不能把超时或服务端故障解释为无资格。页面重新获得焦点时重新核验；下载接口始终独立校验，前端状态不是授权依据。

登录成功自动回到官网原下载页面，重新查询资格；不自动开始文件下载。站点生成固定本站路径的返回地址，不接受任意外部跳转地址。沿用 Auth 现有登录、二次验证与 redirect 处理，不新建登录表单或身份系统。

## 接入现有 Auth

代码核验：Auth 的生产配置支持 cqu.moe 跨子域会话，现有登录页支持受限 redirect；`GET /api/v1/cqu/quicklogin` 的返回为 `{ data: ... }`，其中 `eligible` 表示使用资格。当前设备模式下资格来自 QuickLogin policy，不能仅凭旧权益字段、用户总开关、设备是否已启用或设备名额是否已占满自行推算。

官网跨来源查询使用凭据请求，核对既有 CORS 对 `https://quicklogin.cqu.moe` 的支持；缺失时只增加所需精确来源。状态查询与文件下载复用同一服务端资格规则，不向前端暴露完整权益清单，不在 localStorage 保存会话令牌。

## 私有 R2 与下载接口

用户已选择私有 R2 + Auth 每次下载鉴权，不采用可转发的 R2 presigned URL。

建议在 Auth 新增 `GET /api/v1/cqu/quicklogin/download`：

1. 使用现有 session-only 中间件确认会话；未登录返回 401。
2. 使用与资格查询一致的规则确认内测资格；无资格返回 403。
3. 根据请求中的版本读取私有 R2 中已验证的发布记录，再读取对应不可变 ZIP；未指定版本时读取当前版本。只接受约定的版本、文件名及对象前缀，不接受客户端提供 bucket、对象路径或远程 URL。
4. 以流式响应返回 ZIP，设置安全的文件名、`Content-Type: application/zip`、`Content-Disposition: attachment` 和 `Cache-Control: private, no-store`。鉴权响应不能进入公共 CDN 缓存。
5. 包不存在、R2 故障或配置缺失时明确失败，不回退到公共下载或误报资格不足。所有可返回文件内容的方法均先鉴权。

下载直接导航到 Auth 同源接口，浏览器携带会话，不把整个 ZIP 拉入前端内存。下载前资格检查可改善过期提示，但不能代替接口校验。对跳转后才发生的 401/403/存储故障提供可读错误与返回官网入口，避免呈现裸 JSON。

R2 禁用公共访问，不开启 r2.dev 或公开桶域名。使用 Worker binding，不给官网下发 S3 密钥。版本对象不可变，保留旧包；“当前版本”只在对象与 SHA-256 验证完成后切换。官网与 Auth 下载接口读取同一份已核验发布元数据。Auth 提供不含下载凭据的公开版本信息，官网据此显示版本、文件名、大小和 SHA-256。前端点击下载时携带已展示的版本，服务端仅接受发布记录中已验证的版本并重新鉴权，保证用户所见摘要对应实际下载文件；版本不存在时要求刷新，不静默换包。

该机制限制从本站取得安装包，不能阻止获准用户转发已下载的 ZIP；插件实际使用仍由现有设备授权控制。

## 实现边界与部署提案

- 官网放在 QuickLogin 仓库的独立 `website/` 目录，优先复用现有 Vite、TypeScript 与普通 CSS，构建为多页静态站，不引入应用框架或 CMS。
- 网站单独输出到 `website/dist/`，通过 Cloudflare 静态资源托管部署至 quicklogin.cqu.moe；不能混入扩展 dist 或 canary ZIP。
- Auth 仓库仅修改所需下载路由、共享资格检查、R2 binding、相关类型与测试，不调整学校登录或会话同步策略。
- 实施时检查并优先复用干净且空闲的 QuickLogin Auth 隔离工作区；不修改无关脏工作区。
- 按项目发布规则处理服务行为变更所需版本，保持三个根版本一致。门户发布、Auth 部署、R2 上传、本地插件包与 Chrome Web Store 发布分别记录。
- 当前仅确认 ZIP + 开发者模式安装；Chrome Web Store 上传与发布不在本次范围。

## CI 与自动发布

用户已确认：推送版本标签才发布插件；普通代码合并不发布新插件包。此处 publish 指发布到本站私有 R2 下载渠道，不包含 Chrome Web Store。

现状：QuickLogin 没有 CI 工作流；已有 Vite 构建会输出源码提交、插件版本、协议版本和契约摘要，check:package 可复用。Auth 已有 main 自动部署流程，插件发版不触发 Auth 重新部署。

| 流程 | 触发 | 结果 |
| --- | --- | --- |
| 检查 | PR、分支 push | npm ci、typecheck、test、build、check:package 及官网构建；无发布凭据 |
| 官网部署 | main 上官网及其构建配置变化 | 通过检查后更新官网，不发布插件包 |
| 插件发布 | 推送严格匹配 vX.Y.Z 的标签 | 验证、生成 ZIP、上传私有 R2、更新当前 canary 版本 |

发布标签必须指向 main 历史中的提交。标签与 package.json、package-lock.json、public/manifest.json 版本必须一致。版本变更先提交，CI 不临时修改版本。可信标签发布使用受限生产凭据，普通检查不读取这些凭据。

### 发布顺序

1. 从标签提交执行干净安装与全部发布门禁；核验 build-info 源码提交等于该提交、协议契约与预期一致。
2. 仅打包 dist 内容，生成 releases/cqu-quicklogin-<version>-canary.zip。固定归档顺序、时间等元数据；检查 ZIP 清单、manifest、CRC、解压后内容，计算 SHA-256 与字节数。
3. 生成版本发布记录：版本、文件名、R2 对象键、源码提交、协议版本、契约摘要、大小、SHA-256、发布时间、CI run 和面向用户的更新说明。
4. 上传私有 R2 的 quicklogin/releases/<version>/。禁止覆盖既有版本；重跑只允许在来源与完整文件验证一致后复用，否则要求新版本。
5. 从 R2 重新下载包并校验实际内容。通过后才用单个完整 JSON 对象更新 quicklogin/channels/canary.json，原子切换当前版本及其摘要。网站与 Auth 据此获得新版本，不为每个插件包重新部署 Auth。
6. 所有插件发布共享一个串行并发组，发布中不被新任务取消；切换前比较版本，旧任务重跑不能自动降级。显式手动回滚仅指向已验证旧包，不覆盖版本文件。
7. 读回当前指针及公开版本接口，执行无登录和无资格的拒绝下载验证，并通过受控方式验收有资格下载。记录发布各阶段；上传和校验失败保持旧指针，切换后验收失败明确报告并支持回滚，不把上传成功等同完整验收。

网页可以公开版本号与校验信息，不能公开 ZIP 或可免鉴权下载的签名链接。R2 公共访问关闭，包不进入静态站或公开 GitHub Release 附件。受控响应与当前版本信息不使用公共缓存，历史对象保留用于校验及回滚。

首次初始化配置私有桶、目标桶范围的 CI 写入凭据、Auth R2 binding 和官网域名。官网部署凭据与插件上传凭据按职责分开，凭据不出现在前端、包内容或日志中。后续推送版本标签自动完成发布。

生成发布报告，并以可审阅文档变更同步 quicklogin-release.md 与 quicklogin-handoff.md 的源码提交、包名和 SHA-256；Auth 变更另记提交与 Worker 版本。不靠自动向 main 提交触发循环发布。合成测试、真实登录下载、R2 上传与站点部署分别记录。

用户已确认不做扩展自动更新，也不增加本地更新助手或插件内新版检查。CI 只自动发布安装包；用户登录并通过资格校验后下载 ZIP，按指南覆盖原加载目录并手动重载扩展。

## 验收

1. 三种用户状态分别得到准确文案；无资格用户没有申请通道。
2. 登录与二次验证完成后返回官网原下载页，按钮重新计算，不自动下载。
3. 未登录、资格撤销、伪造前端状态、直接访问下载 URL 均不能取得包；服务故障不能放行。
4. 有资格用户得到正确 ZIP，文件名、manifest、包内容、完整性和 SHA-256 与发布元数据一致。
5. R2 公共入口不可用，受保护响应无公共缓存绕过；下载不写出学校 Cookie、token 或私密日志。
6. 桌面与手机布局、键盘操作、加载/错误/重试、主要浏览器链接和图文步骤经过检查。
7. 运行 QuickLogin 的 typecheck、test、build、check:package，并验证官网独立构建；Auth 运行所涉及的类型与路由测试。真实登录下载与合成测试分别记录。
8. CI 版本不匹配、门禁失败、上传失败或读回摘要不一致不切换当前版本；重跑不覆盖历史包，旧版本任务不降级，显式回滚只切换已验证指针。
