# 学校仍要求登录但扩展显示已就绪

日期：2026-10-15（Asia/Shanghai）。诊断基线：`c410e12` / `0.4.6`。修复候选：`0.4.7`，尚未发布或安装验收。

## 现场与证据边界

用户从 `my.cqu.edu.cn` 进入学校登录页，扩展仍显示“已就绪”；仅等待或刷新约 3–5 分钟后，出现“当前可用，正在重试续期”，随后恢复。通过 Chrome 扩展管理页面只读确认安装版本为 0.4.6，观察时学校业务页面已恢复。

没有采集 token、Cookie 值、密码、验证码或 ticket。测试的错误码、三分钟冷却和会话均为合成输入，不能证明当时线上失败的原因。

## 根因与红灯证据

真实消息处理、sync、Cookie 写入及读回、storage、popup 投影组成回归边界；只替换 Auth API 与 Chrome 宿主。修复前 3 个断言全部失败：

| 检查 | 预期 | 0.4.6 实际结果 |
| --- | --- | --- |
| 登录页已上报，Auth 请求尚未完成 | 立即撤下已就绪 | 仍显示已就绪 |
| 登录页已上报，云端处于冷却等待 | 不声称当前可用 | 当前可用，正在重试续期 |
| 旧恢复轮次已完成，本次云端仍等待 | 不使用旧轮次刷新 | 返回 navigating 并刷新 |

原消息处理器先等待网络 sync，首次表单反馈未写入 `schoolAccess=login_form_seen`；只有自动导航后仍出现表单时才记录。云端可用期推断与 Cookie 字节一致性因此掩盖了学校实际拒绝。

同时，旧 `recovery.phase=finished` 在冷却返回时仍被当成当前页面恢复完成，缺少 tab/document 和本轮写入关联。

原独立探针分别只补页面反馈、只清旧轮次，得到 2/3、1/3 通过；两者同时启用为 3/3。探针现已移入正式测试并去掉条件补丁；当前回归不修改被测实现，也不 mock sync。

## 修复边界

- 首次确认表单立即持久化拒绝事实，快速返回提示，不等待 Auth。popup 和页面共享安全状态投影；此时忽略云端对旧会话可用性的估计。
- 持久化独立学校页面恢复轮次，关联被拒绝的会话元组及等待文档。Cookie 缺失可重新应用；managed Cookie 被拒绝才请求真实会话恢复；外来 Cookie 继续由原所有权检查保护。
- 新写入成功且 ACK 完成后，每个等待文档最多导航一次；新页面再次显示登录表单时停止自动恢复。显式重试才重新创建轮次。
- 内容脚本接收按 documentId 发送的无敏感信息通知，再读取安全摘要。可信存储访问限制保留，通知不包含存储值。前台每 5 秒异步对账，通知合并为有界尾随读取，页面隐藏或用户输入时停止主动检查。
- 手动输入、关闭开关及授权清除撤销本轮；晚到响应沿用 generation 边界，不能覆盖新意图。共享生成协议文件未改动；不需要 Auth 端修改。

Chrome API 依据：[storage 访问级别](https://developer.chrome.com/docs/extensions/reference/api/storage)、[按文档发送消息](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-sendMessage)。

## 仍需单独验收

源码修复与自动化不等同于用户 Chrome 已升级，也不等同于真实学校业务访问成功。官网 canary、安装升级及 `my.cqu.edu.cn` 登录验收分别记录于发布交接。

扩展后台 alarm 至少间隔 30 秒、空闲周期 5 分钟，学校重试受服务端 retryAt 约束。诊断还只读核对了本地 Auth `2c30480ef63fd793bde3974e55864a4bb12caca2` 的分钟级退避，但未核对当时线上部署。缺少当时请求时间线，不能把实际 3–5 分钟全部归因于轮询，也不能断言学校风控、验证码或网络故障。
